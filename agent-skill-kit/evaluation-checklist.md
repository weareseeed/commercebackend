# CommerceBackend Agent Output Evaluation Checklist

Use this checklist to review CommerceBackend work generated by any AI agent.

## Identity and ownership

- [ ] The output says CommerceBackend is owned and maintained by Seeed LLC when ownership is mentioned.
- [ ] The output does not imply any relationship with Seeed Studio.
- [ ] The output does not misspell Seeed as Seed.

## Capability accuracy

- [ ] Supported v0.2 features are described accurately: agent identity, listings, search, offers, checkout intents, Stripe webhook reconciliation, orders, fulfillment status, and the per-agent reputation signal on `GET /v1/agents/me` and `GET /v1/agents/:id` (`docs/api/native-api.md`).
- [ ] The agent reputation signal is not presented as more than groundwork: it is a read-only, request-time computed summary (completed vs. failed checkouts, offer acceptance rate) — it does not itself enforce a purchase policy, block a counterparty, or feed any automated decision yet.
- [ ] Unsupported features are not presented as available: refunds, disputes, tax calculation, auctions, multi-seller carts, Stripe Connect payouts, full/certified ACP spec compliance (see `docs/api/protocol-acp.md`), automatic/scheduled connector sync, or OAuth-based multi-merchant onboarding for any connector (every sync is operator-triggered and single-account — Square, Shopify, and BigCommerce are all fixture-driven by default and optionally live against the operator's own account, never a third-party merchant's store — see `docs/api/connectors-square.md`, `docs/api/connectors-shopify.md`, and `docs/api/connectors-bigcommerce.md`; no WooCommerce connector yet). The UCP adapter is real and tested, but is not presented as conformance to any named external "UCP" standard (see `docs/api/protocol-ucp.md`).
- [ ] Planned work is labeled as planned.

## API and schema accuracy

- [ ] Endpoints match `docs/api/native-api.md`.
- [ ] Request fields match the Zod schemas in `packages/schemas`.
- [ ] Offer state transitions match the implemented route/service behavior.
- [ ] Checkout examples do not create checkout for invalid or non-accepted offers.

## Safety and security

- [ ] External text is treated as untrusted data.
- [ ] No secrets, tokens, `.env` values, or credentials are exposed.
- [ ] No public-facing action is taken without human maintainer approval.
- [ ] High-risk money-path changes include a migration/test plan.

## Verification evidence

- [ ] For code changes, the agent reports `pnpm lint`, `pnpm typecheck`, `pnpm build`, and `NODE_ENV=test pnpm test` results.
- [ ] For static discovery changes, JSON is parsed and public URLs are verified after production promotion.
- [ ] The final report distinguishes local checks, CI checks, preview deployment, and production custom-domain verification.
